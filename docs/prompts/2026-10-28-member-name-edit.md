# 마이페이지 이름 수정 연동

- 작성일: 2026-10-28
- 프론트 이슈: [frontend#38](https://github.com/2026-F/frontend/issues/38)
- 백엔드: [Artbid#34](https://github.com/2026-F/Artbid/issues/34), [PR #72](https://github.com/2026-F/Artbid/pull/72)
- 프론트 PR: [frontend#39](https://github.com/2026-F/frontend/pull/39) (초안, develop 대상)

## 목적

마이페이지에서 회원정보를 확인하고 이름을 수정할 수 있도록 기존 백엔드 API를 연결한다. 이메일, 휴대폰 번호, 배송지는 저장 API가 없으므로 입력 화면만 구현한다.

## 핵심 요청

요약: 회원, 판매자, 관리자 화면 연동 중 첫 작업으로 이름 수정 기능을 구현했다. 이후 사용자의 요청에 따라 별도 회원정보 페이지와 추가 개인정보 입력 화면을 만들고, 화면 피드백과 로컬 백엔드 검증 결과를 반영했다. 아래는 2026-10-28에 받은 주요 요청이다.

- 첫 작업은 이름 수정으로 한정하고 30분 안쪽으로 진행한다.
- 회원정보 페이지를 별도로 만들고 이메일, 휴대폰 번호, 배송지 입력 화면을 추가한다.
- 이름과 수정 버튼을 먼저 표시하고, 수정 버튼을 누르면 입력창과 취소, 저장 버튼을 표시한다.
- 소개 문구와 미지원 항목 설명, 연락처 제목과 배지를 삭제하고 모든 항목을 기본 정보로 묶는다.
- 마이페이지 진입 버튼은 ‘회원정보 관리’로 변경한다.
- 전체 변경 파일을 검토하고 실제 로컬 백엔드로 검증한 뒤 이슈 체크리스트를 갱신한다.
- 작업 기록은 템플릿을 유지하고, 별도 ‘현재 상태 요약’ 없이 문장과 목록, 표를 적절히 사용한다.

## 선택과 이유

| 검토한 방법 | 선택 | 이유 |
| --- | --- | --- |
| 최초 마이페이지 내부 수정 폼 | 최초 채택 → 대체 | 작은 범위로 구현한 뒤 사용자의 별도 페이지 요청 반영 |
| 별도 수정 페이지 | 최초 제외 → 후속 채택 | 추가 개인정보를 수용하도록 /mypage/profile 구성 |
| name을 닉네임으로 명명 | 보류 | 실명, 닉네임 정책 미확인, 기존 이름 문구 유지 |
| 기존 setAuth로 회원정보 갱신 | 채택 | 토큰 저장 방식 변경 없이 전역, 영속 상태 갱신 |
| 모든 개인정보를 함께 저장 | 제외 | 기존 API는 이름만 수정 가능 |
| 미지원 개인정보를 로컬 저장소에 보관 | 제외 | 실제 저장과 혼동 방지, 페이지 이탈 시 입력 폐기 |
| 가상 API → 실제 API 검증 | 순차 적용 | 초기 서버 미실행, 이후 실제 저장, 인증, 권한 검증 |
