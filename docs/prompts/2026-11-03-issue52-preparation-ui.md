# FE #52 미제공 기능과 프로모션 표시

- 작성일: 2026-11-03
- 관련 이슈: [FE #52](https://github.com/2026-F/frontend/issues/52)

## 목적

시연 화면에서 실제로 제공하지 않는 기능이나 출품 정보를 제공 중인 것처럼 보이지 않게 한다.

## 핵심 요청

요약: 사용자가 승인한 FE #52 작업을 리뷰하기 쉬운 세 PR로 분리한다. 첫 PR은 공통 API 타입과 오류 UI, 미제공 기능과 프로모션의 준비 중 표시를 다룬다. 프롬프트 기록은 템플릿에 따라 각 PR별로 나눈다.

## 선택과 이유

| 방법 | 선택 | 이유 |
| --- | --- | --- |
| 미동작 기능 자리를 유지하고 준비 중으로 표시 | 채택 | 시연 화면의 기능 상태를 알 수 있다. |
| 프로모션 편집 콘텐츠와 실제 출품을 구분 | 채택 | 배너와 소개가 실제 경매나 방송으로 오해되지 않게 한다. |
| 작품 조회 변경을 다음 PR에 포함 | 채택 | 변경 주제별로 검토할 수 있다. |

## 반영 내용

공통 API 타입 및 서버/브라우저 주소, 오류·이미지 공통 UI를 준비한다. 프로모션, 라이브 편성, 마이페이지 통계와 미동작 검색·알림을 준비 중으로 표시한다. 입찰·거래 기능은 변경하지 않는다.

## 검증

| 확인 항목 | 방법 | 결과 |
| --- | --- | --- |
| 빌드 | `frontend/`에서 `next build` | 성공. 이미지·폰트 lint 경고가 남았다. |
| 화면 | 전체 변경 검증 당시 로컬 브라우저 확인 | 프로모션 준비 중과 관리자·판매자 화면 진입을 확인했다. |

미검증: 이 분리 브랜치 단독의 전체 브라우저 회귀와 배포 환경은 확인하지 않았다.

## 남은 작업

후속 PR에서 작품·경매 실데이터 연결과 3D·공간 미리보기를 각각 처리한다. 이 PR만으로 기존 목록·상세의 목데이터 대체가 제거되지는 않는다.


## 2026-11-04 PR #55 리뷰 반영

- 요청 요약: 미사용 프로모션 링크 삭제, 준비 중 문구 통일, 목데이터 ID 분리를 기존 PR 브랜치에 커밋한다.
- `primaryLink`, `secondaryLink` 타입과 데이터를 삭제하고 상세 상단에 캐러셀과 같은 준비 중 표시 조건을 적용했다.
- 작품 ID 1~6에 경매 ID 101~106을 연결했다. 작품 상세와 목록의 `auctionId`, 경매의 `id`를 함께 맞췄다.
- ID 분리 시 기존 `getLot`이 작품 ID로 경매를 검색해 상세를 찾지 못하므로 경매 ID로 비교하도록 최소 수정했다. 작품 ID로 쓰는 `getMockLot`, 방송의 `lotIds`와 `currentLotId`는 유지했다.
- #56의 실제 API 조회 개편과 겹치는 부분은 후속 PR 통합 시 확인한다. API 계약은 변경하지 않았다.
- 검증: lint 통과(이미지·폰트 경고), 여섯 목데이터의 ID 연결 일치와 경매 ID 조회 성공 및 작품 ID 조회 거절 검증 통과, `git diff --check` 통과.
- 미검증: 실제 백엔드 연동과 브라우저 화면 회귀.
- 추가 검증: production build 통과. 생성된 프로모션 HTML 5개에서 준비 중 표시와 기존 경매 문구 미노출을 확인했다. 외부 Google Fonts 다운로드 실패로 폰트 최적화는 생략됐다.
