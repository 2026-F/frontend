# 관리자 작품 승인 및 반려 화면

- 작성일: 2026-10-29
- 관련 이슈 / PR: 프론트 [#43](https://github.com/2026-F/frontend/issues/43), 백엔드 [#36](https://github.com/2026-F/Artbid/issues/36), 선행 프론트 [#42](https://github.com/2026-F/frontend/pull/42). 이번 PR은 미생성.

## 목적

관리자가 앱에서 심사 대기 작품을 찾아 제출 내용을 검토하고 승인하거나 반려할 수 있도록 기존 API를 연결한다.

## 핵심 요청

> 관리자 작품 승인·반려 화면 구현 계획한 대로 구현해줘

요약: 사용자 선택에 따라 기존 모바일 앱 스타일을 유지하고 판매자 브랜치에서 분기한다. 작업 이슈 #43을 먼저 발행했다. 구현과 로컬 검증까지만 진행하며 커밋, 푸시, PR 생성과 병합은 별도 요청 후 수행한다.

후속 요청: 사용자가 커밋 메시지와 PR 본문을 검토한 뒤 PR 발행을 요청했다. `feat: 관리자 작품 심사 목록 및 승인/반려 화면 구현`으로 커밋하고 `feat: 관리자 작품 승인/반려 화면 및 API 연동` 제목으로 PR을 생성한다.

## 선택과 이유

| 검토한 방법 | 선택 | 이유 |
| --- | --- | --- |
| 넓은 관리자 전용 레이아웃 | 제외 | 사용자가 기존 앱 스타일 유지 선택 |
| 판매자 PR 병합 대기 | 제외 | 사용자가 현재 브랜치에서 분기 선택 |
| 공개 목록 함수 확장 | 제외 | 기존 반환값과 공개 목록 호출에 영향을 주지 않도록 관리자 페이지 조회 함수 추가 |
| 공개 상세 페이지의 목데이터 대체 | 제외 | 실제 심사 데이터와 서버 오류만 표시 |
| 승인과 반려 즉시 실행 | 제외 | 취소에 기본 포커스를 둔 확인 대화상자 제공 |
| 처리 실패 시 자동 재전송 | 제외 | 결과 불명 상태에서 중복 처리를 줄이기 위해 최신 상태 확인 후 재시도 |
| 반려 사유와 재심사 | 제외 | 기존 API 미지원. 제품 정책을 새로 만들지 않음 |

## 반영 내용

- 브랜치: feature/admin/artwork-review. 선행 판매자 브랜치 308dff0에서 분기.
- ADMIN 전용 마이페이지 메뉴와 /admin 공통 접근 안내. 인증정보 확인 후에만 하위 심사 화면을 렌더링한다.
- /admin/artworks: 심사 대기 목록, 최신순 20개, URL 페이지 유지, 빈 목록, 재시도와 이전 유효 페이지 복귀.
- /admin/artworks/[id]: 사진, 작가와 위탁자, 설명, 재료와 크기, 가격, 등록일, 보증서 및 영상·3D 링크 검토.
- 승인 또는 반려 확인, 처리 중 중복 방지, 204 성공 후 상세 재조회, 409 최신 상태 복구, 결과 불명 시 최신 상태 확인 전 제출 차단.
- 같은 페이지라도 세션이 바뀌면 하위 컴포넌트를 다시 생성하고 이전 세션의 늦은 응답을 무시한다.
- 실제 HTTP/HTTPS URL만 열고 누락 정보와 이미지 실패는 안내로 표시한다.
- scripts/local-admin-review-fixtures.mjs: 로컬 전용 일반 회원, 판매자, 관리자와 작가 및 작품 생성. 비밀번호는 환경변수에서 받아 출력·파일 저장하지 않는다.

### 현재 서버 계약

| 항목 | 확인한 내용 |
| --- | --- |
| 목록 | GET /api/artworks?status=PENDING_REVIEW&sort=latest&page=0&size=20 |
| 상세 | GET /api/artworks/{artworkId} |
| 처리 | POST /api/artworks/{artworkId}/approve 또는 /reject, 성공 204 |
| 상태 | 승인 PREVIEW, 반려 REJECTED. 이미 처리된 상태는 409 ARTWORK_NOT_EDITABLE |
| 권한 | 승인과 반려는 JWT 역할 ADMIN 검사. 비로그인과 잘못된 토큰도 현재 403 ARTWORK_FORBIDDEN |
| 조회 접근 | 대기 목록과 상세는 공개 API. 화면 접근 제한이 서버 조회 권한 보장을 의미하지 않음 |
| 미존재 처리 | 상세 조회는 404지만 처리 API의 미존재 작품은 IllegalArgumentException으로 400이 될 수 있음 |
| 범위 | 승인만으로 경매 생성·시작 안 함. 반려 사유·재심사 API 없음 |

### 수동 확인용 데이터

프론트 저장소 루트의 Git Bash에서 실행한다. Docker PostgreSQL과 로컬 백엔드가 필요하며 Node.js 20 이상을 사용한다. 실행마다 새 계정과 대기 작품 2개를 만들고 수동 확인용으로 유지한다.

```sh
read -s -p '로컬 테스트 비밀번호(8~64자): ' ARTBID_TEST_PASSWORD
export ARTBID_TEST_PASSWORD
export ARTBID_TEST_API_ORIGIN=http://127.0.0.1:8082
node scripts/local-admin-review-fixtures.mjs
unset ARTBID_TEST_PASSWORD ARTBID_TEST_API_ORIGIN
```

출력된 ADMIN 이메일과 직접 입력한 비밀번호로 로그인한다. 기본 API 포트는 8080이며 실제 로컬 서버에 맞춘다. 자동 QA는 생성한 ID와 계정·작가 조건으로 한정해 데이터를 정리한다. 기존 작품과 계정의 상태를 변경하지 않는다.

## 남은 작업

- 로컬 구현과 핵심 API·브라우저 검증을 완료했다. 수동 확인용 계정과 작품은 위 스크립트로 별도 생성한다. 자동 QA 데이터는 정리했다.
- 후속 사용자 요청으로 커밋, 푸시와 PR 발행을 진행한다. 이슈 체크리스트 변경과 병합은 이번 요청에 포함하지 않는다.
- 모바일 실기기와 서버의 동시 처리 원자성은 별도 검증 대상으로 남긴다.
- PR 발행 전 확인 결과 선행 #42는 미병합이다. 관리자 변경만 표시하도록 판매자 브랜치를 임시 PR 대상으로 삼는다. #42 병합 후 develop 대상으로 변경하고, squash 병합이라면 관리자 커밋만 develop 위에 다시 배치한다. 판매자 브랜치로 병합하지 않도록 PR에 명시한다.
- 서버의 비공개 작품 조회 접근 정책은 팀 확인 사항으로 남긴다.
