# MY 판매자 지급 내역

- 작성일 2026-11-25
- 관련 이슈 [프론트엔드 #96](https://github.com/2026-F/frontend/issues/96)

## 목적

판매자가 MY에서 지급 대기·완료 합계와 낙찰 건별 지급 내역을 확인하도록 한다.

## 핵심 요청

요약 · 기존 판매자 지급 조회를 사용해 지급 목록을 만들고, 배치 반영 시점과 빈 목록·조회 실패·권한 상태를 안내한다. 모바일 화면과 로컬 백엔드에서 검증하고 운송장 관리는 후속으로 진행한다.

## 선택과 이유

| 선택 | 이유 |
| --- | --- |
| 기존 지급 API의 합계·순서 사용 | 수수료와 지급액의 서버 계산 결과를 그대로 보여 준다. |
| 배치 안내와 화면 새로고침 | 배치가 지급 건을 만든 뒤 조회 결과가 바뀌며, 사용자가 같은 화면에서 확인할 수 있다. |
| 회원 ID·토큰별 조회 | 계정 전환과 로그아웃 직전에 요청한 이전 회원의 내역이 나타나는 것을 막는다. |

## 반영 내용

- MY 판매자 메뉴의 지급 내역을 `/mypage/seller/payouts`에 연결한다. 서버 합계와 건별 낙찰가·판매 수수료·지급액, 지급 상태를 표시한다.
- 비로그인·401은 로그인, 비판매자·403은 접근 안내, 네트워크·서버 오류는 다시 시도를 제공한다. 빈 목록과 배치 반영 지연을 표시한다.

## 검증

| 확인 항목 | 방법 | 결과 |
| --- | --- | --- |
| 정적 검사 | `npm run lint`, `npx tsc --noEmit`, `npm run build` | 통과. 기존 ESLint 경고 출력 |
| 지급 배치와 데이터 격리 | 백엔드 `main`, 로컬 PostgreSQL·Redis, Chrome 390px와 JWT HTTP 요청 | 브라우저에서 배치 전 0원·빈 목록, 배치 후 새로고침으로 판매자 A의 지급 대기 두 건·합계 확인. 판매자 B로 전환하면 0원·빈 목록. HTTP에서 최신순, 구매자 빈 목록, 비로그인 401 확인 |
| 모바일 화면과 오류 | Chrome 390px, 모의 응답 | 메뉴·새로고침·빈 목록·지급 완료 표시·재시도·401/403 안내·계정 전환 및 지연 응답 확인 |

## 남은 작업

- 실제 운영 데이터와 모바일 실기기 확인, 지급 건의 운송장 등록·수정은 후속 범위다.

## 2026-11-25 PR 리뷰 후속

- 다른 탭의 로그아웃·계정 전환은 현재 탭의 Zustand 상태를 자동으로 갱신하지 않는다. 공유 토큰 변경을 구독하고 저장된 인증 상태를 복원해 이전 내역을 숨긴다.
- 응답 반영 시에도 공유 토큰을 확인해 세션이 바뀐 뒤 도착한 이전 요청을 버린다. 기존 주문 화면의 세션 확인 방식과 일치시킨다.
