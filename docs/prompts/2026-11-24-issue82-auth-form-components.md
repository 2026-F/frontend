# 로그인·회원가입 폼 공통화

- 작성일 2026-11-24
- 관련 이슈 [frontend #82](https://github.com/2026-F/frontend/issues/82)

## 목적

로그인·회원가입의 제출 버튼과 입력 필드 스타일을 공통화하고, 입력값이 있어도 보조기술에서 각 필드 이름을 확인할 수 있게 한다.

## 핵심 요청

> 이거 검토하고 해결할 작업 시작해줘

> develop에서 새로운 브랜치 만드는거지 당연히?

이슈의 적용 범위는 로그인과 회원가입이다. 기존 화면과 제출 상태, 유효성 검사, 오류 문구, API 요청 및 성공 후 이동을 유지한다.

## 선택과 이유

| 선택 | 이유 |
| --- | --- |
| 입력과 연결된 시각적으로 숨긴 `label` 사용 | 기존 배치와 플레이스홀더를 유지하면서 각 입력에 접근 가능한 이름을 제공한다. |
| 라임색과 기본 텍스트에 #71의 토큰 사용 | 입력 테두리와 포커스는 기존 색상 값으로 공통 컴포넌트에서 관리한다. |
| 회원가입 비밀번호 길이 오류를 해당 필드와 연결 | 필드 오류와 서버에서 반환한 폼 오류를 구분해 전달한다. |

## 반영 내용

- `develop`의 `4dfbb6f`에서 `fix/82-auth-form-components` 브랜치를 만들어 별도 worktree에서 작업한다.
- 두 화면에 공통 `Button`과 `FormField`를 적용하고 기존 인증 핸들러의 요청 순서와 이동 경로를 유지한다.

| 모바일 화면 비교 | Chromium 390×844 에뮬레이션에서 변경 전후 캡처 비교 | 두 화면의 기본·포커스·서버 오류·제출 중 상태와 회원가입 비밀번호 오류 상태까지 총 9쌍의 픽셀이 일치했다. |

| 제출 흐름 | 모의 응답으로 두 화면의 요청과 상태 검증 | 제출 중 버튼 비활성화, 실패 메시지와 재활성화, 로그인 회원정보 재시도, 회원가입 직후 자동 로그인, 성공 시 `/mypage` 이동을 확인했다. |

### 실제 백엔드 연동

> 실제 백엔드랑 모바일까지 검증해봐

ArtBid 백엔드 `develop`의 `1915fb7`을 빌드하고 별도의 로컬 PostgreSQL·Redis로 실행했다. Chromium 모바일 에뮬레이션 360×800, 390×844에서 각각 터치와 키보드로 두 폼을 검증했다.

| 확인 항목 | 결과 |
| --- | --- |
| 회원가입 성공 | 가입 API `201` → 자동 로그인 `200` → `/mypage` 이동 및 가입한 회원 표시 |
| 회원가입 실패 | 비밀번호 길이 오류 시 API 호출 없이 필드에 오류 표시. 중복 이메일은 API `404`와 오류 문구 표시 |
| 로그인 실패 및 복구 | 잘못된 비밀번호는 API `404`와 오류 문구 표시. 비밀번호 수정 후 로그인 `200`, 회원 조회 `200`, `/mypage` 이동 |
| 제출·접근성 | 제출 중 버튼 비활성화와 로딩 문구, 오류 후 재활성화, Tab 순서, 입력 후 접근 가능한 이름 확인 |

테스트 계정은 로컬 검증 DB에만 생성했다. 사용자 요청에 따라 모바일 실기기 검증은 이번 작업 범위에서 제외했다.

### 2026-11-24 PR #86 리뷰 반영

> 고치렴

- 회원가입 비밀번호에 처음부터 길이 안내를 연결한다. 길이 오류가 발생하면 오류 문구를 필드 설명으로 연결하고, 유효한 길이로 수정하면 필드 오류를 지우고 안내를 다시 연결한다. [P2 리뷰](https://github.com/2026-F/frontend/pull/86#discussion_r4674090980) · [P3 리뷰](https://github.com/2026-F/frontend/pull/86#discussion_r4674090988)
- Chromium 390×844에서 접근성 트리의 길이 설명, 7자·65자 거절, 8자·64자 수정 직후 오류 해제를 확인했다. 모의 API로 서버 오류 유지 및 로그인·회원가입 성공 후 이동을 확인했다.
- `npm run build`에서 빌드, 린트, 타입 검사가 통과했다. 기존 이미지·폰트 경고가 출력되었다. 실제 백엔드 연동과 모바일 실기기는 이번 수정에서 재검증하지 않았다.
