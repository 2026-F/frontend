판매자의 실제 역할을 유지해 로그인하고, 본인 판매자 프로필을 등록하고 수정할 수 있도록 기존 API를 연결한다.

요약: 이름 수정 브랜치의 리뷰 fix 6ca99de를 기준으로 별도 브랜치에서 구현한다. 로컬 구현과 검증까지 수행하고 커밋, 푸시, GitHub 변경은 별도 요청 후 진행한다.

후속 요청: 비로그인 판매자 페이지의 안내만 기존 로그인 화면과 유사한 UI로 수정하고 작업 이슈를 발행한다. 사용자 요청에 따라 #41을 소급 등록했다. 커밋, 푸시, PR 생성은 요청 범위에 포함하지 않는다.

PR 발행 요청: 이후 사용자가 커밋과 푸시를 포함한 PR 발행을 요청했다. 제목은 `feat: 판매자 프로필 등록/수정 및 로그인 역할 처리 보완`으로 확정했다. 로그인 보완과 판매자 기능을 두 커밋으로 나누고 develop 대상 PR을 생성한다.

## 선택과 이유

| 검토한 방법 | 선택 | 이유 |
| --- | --- | --- |
| 회원 조회 실패 시 임시 BIDDER 생성 | 제거 | 실제 판매자의 역할과 이름을 임의로 바꾸지 않음 |
| 로그인 토큰 즉시 영속 저장 | 변경 | 회원 조회 성공 전에는 화면 메모리에만 보관하고 성공 후 기존 setAuth로 확정 |
| 기존 JWT와 영속 저장 체계 변경 | 제외 | 로그인 준비 단계만 보완하고 인증 계약은 유지 |
| 토큰을 회원 조회 요청에 명시 | 채택 | 저장 전 요청 가능. 인터셉터는 명시한 Authorization을 덮어쓰지 않음 |
| 조회 실패 후 로그인 전체 재실행 | 선택 가능 | 별도 회원 조회 재시도 제공. 계정 입력 변경 시 임시 토큰 폐기 |
| 판매자 역할 전환 API 추가 | 제외 | 백엔드 계약 범위 밖. 로컬에서 새 테스트 계정만 역할 변경 |
| 이미지 파일 업로드와 미리보기 | 제외 | 첫 버전은 이미지 URL 입력과 저장까지 구현 |

## 반영 내용

- 브랜치: feature/seller/profile-management. 사용자 요청대로 이름 수정 브랜치에서 분기.
- 로그인: 회원 조회 재시도, 401 시 임시 인증정보 폐기, 중복 요청 방지, 화면 이탈과 계정 변경 후 늦은 응답 무시.
- 새 로그인 시작 시 기존 저장 세션을 비워 이전 회원정보와 새 토큰이 혼재하지 않도록 처리.
- 마이페이지에 CONSIGNOR 전용 판매자 프로필 관리 메뉴 추가. /mypage/seller에서 비로그인과 다른 역할의 직접 접근 안내.
- 조회 404와 SELLER_PROFILE_NOT_FOUND를 함께 확인할 때만 등록 폼 표시. 성공 조회는 수정 폼 표시.
- 상호명 trim 후 필수 1~50자, 소개 1000자, 이미지 URL 500자. 이미지 URL은 HTTP 또는 HTTPS만 허용.
- 등록 성공 후 수정 모드 전환. 취소는 마지막 조회 또는 저장 값 복원. 선택 필드 삭제는 빈 문자열로 전송.
- 실패 입력 유지, 조회 재시도, 저장 중 입력 및 버튼 비활성화. 중복 등록 409는 명시적 기존 프로필 재조회로 복구.
- 기존 이메일 readOnly와 미지원 입력 disabled 유지.
- 비로그인 안내의 회색 카드를 제거하고 기존 로그인 화면의 흰 배경, 보조 설명, 높이 48px의 연두색 전체 폭 로그인 버튼을 적용했다. 판매자 등록·수정 폼은 유지한다.
- 로컬 계정 준비: scripts/local-seller-accounts.mjs. 로컬 주소만 허용하고 이번 가입으로 생성한 계정만 역할 변경.

### 백엔드 계약과 한계

| 항목 | 현재 계약 |
| --- | --- |
| API | GET /api/sellers/{memberId}, POST /api/sellers, PATCH /api/sellers/{memberId} |
| 등록 권한 | 유효한 Principal과 CONSIGNOR 역할 필요 |
| 수정 권한 | 유효한 Principal과 본인 여부 검사. 별도 역할 검사는 없음 |
| 회원 조회와 판매자 조회 | 공개 API. 조회 성공은 JWT 검증 완료를 의미하지 않음 |
| 로그인과 회원 역할 | 토큰은 발급 시 역할, 회원 조회는 DB의 현재 역할. 역할 변경 후 재로그인 필요 |
| 이미지 URL | 서버는 길이만 검사. HTTP/HTTPS 형식 검사는 이번 프론트 정책 |
| 수정 상호명 | 공백은 도메인에서 거절되며 404 문자열이 될 수 있으므로 프론트에서 차단 |
| 판매자 전환 | 일반 가입은 BIDDER 고정. 서비스용 판매자 전환 절차는 별도 협의 필요 |

### 로컬 테스트 계정 준비

두 저장소를 같은 상위 폴더에 두고 백엔드와 Docker PostgreSQL을 실행한다. Node.js 20 이상에서 실행한다. 다음은 프론트 저장소 루트의 Git Bash 기준이다. 비밀번호는 화면에 출력하거나 파일에 저장하지 않는다.

```sh
read -s -p '로컬 테스트 비밀번호(8~64자): ' ARTBID_TEST_PASSWORD
export ARTBID_TEST_PASSWORD
export ARTBID_TEST_API_ORIGIN=http://127.0.0.1:8082
node scripts/local-seller-accounts.mjs
unset ARTBID_TEST_PASSWORD ARTBID_TEST_API_ORIGIN
```

- 실행마다 새 일반 회원 1개와 판매자 2개의 로컬 이메일을 출력한다. 입력한 비밀번호로 로그인한다. 재실행 시 기존 계정을 수정하지 않는다.
- 기본 API 주소는 http://127.0.0.1:8080이며 실제 로컬 서버 포트로 맞춘다.
- CLI 실행으로 생성한 계정은 수동 확인용으로 유지된다. 자동 QA는 실행 중 생성한 ID와 이메일에 한정해 판매자 프로필과 회원을 정리한다.
- 운영 계정과 실제 환경 파일은 변경하지 않는다.
