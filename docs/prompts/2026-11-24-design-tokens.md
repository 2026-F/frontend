# 공통 색상 토큰 1차 적용

- 작성일 2026-11-24
- 관련 이슈 [frontend #71](https://github.com/2026-F/frontend/issues/71)

## 목적

반복되는 라임색, 배경색, 글자색을 현재 화면의 색과 상태를 유지하면서 공통 이름으로 관리한다.

## 핵심 요청

요약. 기존 스타일과 색상 사용처를 조사한 뒤 최신 `develop`에서 새 브랜치를 만들고, 같은 역할과 값이 반복되는 대표 사용처부터 토큰으로 전환한다. 확인한 미사용 파일 3개와 `.input-field`를 제거하고 `mock.ts`와 전용 에셋은 보류한다.

## 선택과 이유

| 선택 | 이유 |
| --- | --- |
| 기존 Tailwind 색상 설정에 토큰 추가 | TSX 유틸리티와 전역 CSS의 `@apply`에서 같은 정의를 사용한다. 기존 `--background` 값을 `canvas` 유틸리티에서도 참조한다. |
| 기존 라임 3종과 본문·보조 글자색 유지 | 기본 버튼, 강조 표시, 그라데이션과 채팅 강조 글자의 현재 색을 보존한다. 서로 다른 색을 하나로 맞추는 결정은 Figma 확인 후로 보류한다. |

## 반영 내용

| 토큰 | 1차 적용 위치 |
| --- | --- |
| `canvas`, `surface-muted` | 루트 레이아웃, 홈 카테고리, 경매 목록 안내, 공통 카드 |
| `copy-primary`, `copy-secondary` | 홈, 로그인·회원가입, 경매 목록, 입찰, 라이브 입찰·채팅과 일부 공통 스타일 |
| `lime-action`, `lime-highlight`, `lime-soft` | 로그인·회원가입 버튼, 하단 탭 활성 표시, 경매 목록 선택 표시, 공통 버튼, 입찰·채팅 |

루트 `.DS_Store`, 루트 `package-lock.json`, 미사용 `NotifyButton.tsx`를 삭제했다. 사용처가 없는 `.input-field` 정의도 전역 CSS에서 제거했다. `mock.ts`와 전용 에셋은 DB 반영 여부를 확인할 때까지 보류했다.

## 검증

| 확인 항목 | 방법 | 결과 |
| --- | --- | --- |
| 대표 화면의 색과 상태 | Chrome에서 모바일 뷰포트로 변경 전후 앱을 실행하고 목 API로 동일한 조건을 재현 | 홈 배경·보조 텍스트·활성 탭, 로그인 링크·입력 포커스·로딩 중 버튼, 라이브 시청의 입찰·채팅, 송출 시작 버튼의 기본·호버·비활성 상태 등 20개 지점의 계산된 스타일이 일치했다. |
| 공통 컴포넌트 CSS | 카드·기본 버튼·외곽선 버튼 클래스가 포함된 동일한 HTML로 Tailwind CSS 생성 후, 미사용 입력 정의 제거 전후에는 실제 소스 기준으로 비교 | 두 비교에서 각각 생성된 CSS가 일치했다. |
| 빌드와 정적 검사 | `npm run build`, `npm run lint`, `tsc --noEmit --incremental false` | 통과했다. 이미지·폰트 린트 경고와 빌드 중 외부 Poppins 스타일시트 로드 경고가 있었다. |

홈, 로그인, 라이브 시청, 송출 시작 화면을 모바일 뷰포트에서 변경 전후로 캡처했다. 목 API 검증에서는 실제 카메라·마이크 연결을 사용하지 않았다. Figma 시안과 실제 API·IVS 연동은 미검증이다.
