# 프론트엔드 AI 협업 문서 적용

- 작성일: 2026-10-26
- 관련 이슈 / PR: 미생성
- 작업 브랜치: `docs/ai-collaboration` (기준: `develop`)

## 목적

백엔드와 같은 의사결정 기록 방식 적용. 프론트엔드 README와 검증 안내를 현재 구현에 맞게 갱신.

공통 결정 기록: Artbid 저장소의 `docs/prompts/2026-10-26-ai-collaboration.md` (PR 생성 후 링크 연결 예정)

## 핵심 요청

> PR 템플릿에 AI 활용 부분은 빼고, 이 작업하며 생성된 prompts 히스토리 파일이 뭔지 연결하는 걸로 대체하면 될듯?
> 리뷰시 확인할 사항도 중복되는 듯하니 넣지마

추가 요청 요약:

- 두 저장소의 README, CLAUDE.md, AGENTS.md와 prompts 폴더 구성
- 보안 지침 보강, 중간점 사용 축소
- 기록 양식의 담당자, 사용 도구, 담당자 확인 삭제
- 포괄적인 항목을 나누고 짧은 요약과 표로 정리
- README 검토 제안 반영. 백엔드 Kafka 도입 예정과 Redis 사용 여부 미정 구분
- MSA 분리 예정: 경매/입찰 + 회원/작품, 결제/정산, 라이브 스트리밍. 레포 구조 변경 가능
- 문체는 존댓말 없이 요약체와 하다체만 사용
- README 최종 점검 요청. 명령어는 macOS와 Windows Git Bash 기준으로 통일

## 선택과 이유

| 검토한 방법 | 선택 | 이유 |
| --- | --- | --- |
| 루트에 지침 배치, 실행 위치는 내부 frontend 폴더로 명시 | 채택 | 저장소 이름과 앱 폴더 이름이 같아 생기는 혼동 방지 |
| README의 초기 뼈대 설명 갱신 | 채택 | develop의 인증과 공간 미리보기 등 현재 구현 반영 |
| 실제 API, 목데이터, 실기기 검증 구분 | 채택 | 화면 표시만으로 실제 연동 성공을 판단하지 않도록 구분 |
| main 전용 목업 작품을 develop에 병합 | 보류 | 이번 문서 작업의 범위 밖 |
| 백엔드와 같은 기록 양식 사용 | 채택 | 저장소가 달라도 같은 방식으로 결정 과정 확인 |
| 현재 구현과 후속 설계 분리 | 채택 | 사용자 확인: Kafka 도입 예정, Redis 사용 여부 미정. 프론트 계약 변경 여부는 별도 협의 |
| 일시적인 브랜치 차이는 작업 기록에서 관리 | 채택 | README의 현재 상태 설명이 오래된 고정 규칙으로 남는 문제 방지 |

## 반영 내용

- README: 현재 화면과 API 연동 상태, 실행 명령, 기록 절차 갱신
- CLAUDE.md: 카메라 권한과 자원 해제, 공개 환경변수, 민감정보, 서버 권한 검증 지침 추가
- AGENTS.md: CLAUDE.md를 읽도록 안내
- PR 템플릿: AI 활용 설명과 리뷰 확인 항목 대신 작업 기록 링크
- prompts 폴더: 공통 양식과 이번 작업 기록 추가. 별도 README 없이 루트 문서에서 안내
- 후속 수정: 담당자 관련 필드와 사용 도구 삭제, 불필요한 설명을 덜고 요약과 표로 정리
- README 재검토: 위탁과 프리뷰 흐름, 안티 스나이핑, 화면 PR 스크린샷, 노션 상태 업데이트와 IA/와이어프레임 안내 복원
- 공통 인증 오류 처리의 미구현 상태와 문서별 역할 명시. 확인하지 못한 외부 문서와 요구사항을 추정하지 않도록 지침 보완
- MSA 분리 계획 반영. 현재 코드 경로와 단일 API 주소를 영구 계약으로 간주하지 않도록 안내
- README를 요약체와 하다체로 통일하고 공통 지침에 반영
- 최종 점검: PowerShell 안내 제거, 환경 파일이 없을 때만 복사하도록 수정, 커밋 목록 렌더링과 '필요한다' 표현 수정
- 기록 갱신 규칙을 CLAUDE.md와 TEMPLATE에도 반영. 진행 중인 같은 PR의 이전 판단 보존, 병합 후 새 기록 생성
- 전체 최종 점검: 기술 스택 표 반영, README와 CLAUDE.md의 소스 경로를 저장소 루트 기준으로 통일, PR 기록 링크를 전체 URL과 커밋 영구 링크 안내로 수정
- README 직접 수정본 반영: 노션 상태 업데이트와 IA/와이어프레임 안내는 최종본에서 제외된 상태로 유지
- 조사 시점 develop에 없는 main의 추가 목업 작품은 [PR #34](https://github.com/2026-F/frontend/pull/34) 관련 차이로 기록. 이번 문서 작업에서는 병합하지 않음

## 검증

| 확인 항목 | 방법 | 결과 |
| --- | --- | --- |
| 작업 기준 | 변경 유무와 브랜치 확인 | 변경 없는 상태에서 develop 기준 문서 브랜치 생성 |
| 실행 안내 | package.json, CI, 환경변수 예시와 대조 | 설정 기준 확인 완료, 명령 실행은 미검증 |
| 문서 형식 | `git diff --check`, UTF-8 깨짐 검사 | 통과 |
| 문서 연결 | 상대 Markdown 링크 대상 확인 | 통과 |
| 공통 양식 | 두 저장소의 AGENTS.md, TEMPLATE.md, PR 템플릿 비교 | 동일 |
| 문서 구성 | PR 섹션과 prompts 폴더 확인 | 제외 요청한 PR 섹션 없음, 별도 README 없음 |
| 전체 최종 점검 | 두 저장소 문서 14개 검사, README 셸 구문 검사 시도 | 링크, 코드 블록, 인코딩, 형식, 공통 양식 일치 통과. Git Bash는 실행 환경의 접근 거부 오류로 시작하지 못해 셸 구문 자동 검사 미완료. 앱 명령은 실행하지 않음 |

미검증:

- 앱 빌드, 브라우저 화면, 모바일, AWS, 백엔드 통합 실행: 문서 변경 범위에서 실행하지 않음
- 새 Claude/Codex 세션의 지침 로딩: 파일 위치와 경로만 확인
