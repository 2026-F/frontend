# 라이브 시청 화면 작품 카드와 입찰 바텀시트

- 작성일: 2026-11-25
- 관련 이슈 / PR: 브랜치 feature/live/bid-sheet (develop 기준). 이전 라이브 PR #77

## 목적

라이브 시청 화면의 입찰 막대를 디자인 시안(05 영상, 06 입찰 패널, 07 입찰 진행)에 맞춰 작품 카드와 2단계 바텀시트로 바꾼다. 백엔드 API는 바꾸지 않는다.

## 핵심 요청

> 라이브 스트리밍 기능 개선을 해야해. 일단 ui 개선부터

요약: 시안 이미지 4장(04 로비, 05 영상, 06 입찰 패널, 07 입찰 진행)을 함께 전달했다.

## 선택과 이유

| 검토한 방법 | 선택 | 이유 |
| --- | --- | --- |
| 04 로비부터 구현 | 보류 | 방송 중 경매 목록 API가 백엔드에 없다. 새 API 계약이 필요해 별도 작업으로 분리 |
| 07을 별도 페이지로 구현 | 제외 | 이동하면 방송과 채팅 연결이 끊긴다. 시트 안의 확인 단계로 처리 |
| 07을 바텀시트 2단계로 구현 | 채택 | 시청을 유지한 채 금액 선택과 비용 확인을 나눈다 |
| 시트를 채팅 영역 안에 그리기 | 제외 | 채팅 스크롤 영역에 잘린다. 셸에 포털 대상을 두고 렌더링 |
| 수수료, 배송비를 프론트 상수로 계산 | 채택 (임시) | 서버 값은 AuctionClosingService 상수(10%, 30,000원)에만 있고 조회 API가 없다. 화면에는 "예상"으로 표시 |
| 시안 문구 "입찰 후 취소할 수 없습니다" 사용 | 제외 | 서버는 내 입찰이 아직 최고가면 취소를 허용한다(BidService.cancelBid). "다른 입찰이 들어오면 취소할 수 없습니다"로 수정 |
| 확인 단계 중 현재가가 오르면 금액 자동 상향 | 제외 | 확인한 금액을 몰래 바꾸지 않는다. 선택 단계로 돌려보내고 안내 문구 표시 |

## 반영 내용

- `components/live/LiveBidBar.tsx`: 흰 작품 카드(썸네일, 제목, 작가와 제작연도, 현재가, 남은 시간, 최고 입찰 중 표시). 누르면 바텀시트. 선택 단계(빠른 금액, 직접 입력, 예상 결제 금액)와 확인 단계(비용 내역, 취소 안내, 제출). 비로그인은 로그인 링크. 진행자 화면(readOnly)은 카드만 표시. 입찰 성공 시 카드에 완료 안내 3초 표시. Esc와 바깥 영역으로 닫기
- `components/live/LivePortraitShell.tsx`: 시트용 포털 대상과 `useLiveOverlayRoot` 추가
- `lib/fees.ts`: 예상 결제 금액 계산 추가
- 작품 정보는 `GET /api/artworks/{artworkId}`로 가져온다. 실패하면 카드에 "경매 #id"를 표시하고 입찰은 그대로 가능

## 2026-11-28 실제 백엔드 연동 확인

로컬 Docker(postgres, redis)와 백엔드 소스(`Artbid` 브랜치 feature/live/live-show, `./gradlew bootRun`)를 띄웠다. 로컬 DB에 테스트 회원 4명, 작가, 작품, 진행 중 경매(#2)를 API로 만들었다. 역할(ADMIN, CONSIGNOR)은 로컬 DB에서 직접 지정했다. 헤드리스 Chrome(CDP, 390x844)으로 `/auctions/2/watch`를 조작했다.
