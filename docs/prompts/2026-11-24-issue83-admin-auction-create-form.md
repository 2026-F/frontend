# 관리자 경매 생성 폼 분리

- 작성일 2026-11-24
- 관련 이슈 [frontend #83](https://github.com/2026-F/frontend/issues/83)

## 목적

관리자 작품 행에서 경매 생성 폼의 입력과 검증을 분리한다. 기존 관리자 동작, API 형식과 오류 문구를 유지한다.

## 핵심 요청

이슈 #83의 요청은 관리자 작품 행에서 경매 생성 폼을 분리하고, 다섯 입력에 라벨을 연결하는 것이다. 기존 검증과 API 동작을 유지하며, 로그인·회원가입 폼 공통화가 반영된 `develop`을 기준으로 작업한다.

## 선택과 이유

| 선택 | 이유 |
| --- | --- |
| 폼을 닫아도 컴포넌트 상태 유지 | 기존에는 작품 행이 유지되는 동안 취소 후 다시 열어도 입력값과 날짜 기본값이 유지됐다. |
| 진행 상태와 오류는 작품 행에 전달 | 생성 요청 중 같은 행의 작품 내리기를 막고 기존 위치에서 오류를 표시한다. |
| 보이는 라벨과 입력을 `useId`로 연결 | 여러 행에서 폼을 동시에 열 수 있고 날짜 입력도 각각 화면에 이름을 표시해야 한다. |

## 반영 내용

- `develop`의 `5c9752d` 기준으로 `fix/83-admin-auction-create-form` 워크트리를 사용한다.
- `AdminAuctionCreateForm`이 입력 상태, 검증, 날짜 변환과 경매 생성 요청을 맡는다. `AdminArtworkRow`는 폼 노출 조건과 생성 성공 후 해당 행 갱신을 맡는다.
